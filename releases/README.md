# Final designs submitted to engineering

**No approved handoff has been issued yet.** The original design, dated live
observations, 49-state draft and open explorations are available for review; none
is a newly approved engineering package.

An approved release is the team's final design for an explicitly defined scope
and source version. Engineering should use its release link, not latest main.
The authoritative structured index is [index.json](index.json).

Each entry must identify the design version, approved source commit, included
change/screen/requirement IDs, exclusions, contracts/copy/tokens/assets, acceptance
evidence, retained artifact checksums, named human approvals and engineering
acknowledgement. Record superseded scope and link implementation work when assigned.

Use `design-vX.Y.Z-rc.N` for candidates and `design-vX.Y.Z` for approved handoffs.
Do not publish a stable release merely to make a draft easy to download. Preserve
issued versions; later changes get a new version and review. The maintainer has not
yet enabled enforcement that locks tags or assets.

See [the handoff gate](../docs/05_Engineering_Handoff.md) and
[the shared workspace model](../docs/06_Shared_Design_Workspace.md). The tech team
can download a release package or clone the repository and check out its named tag.
Implementation, staging verification and live deployment are tracked separately.
