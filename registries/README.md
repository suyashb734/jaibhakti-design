# Design registries

sources.json defines provenance and authority. screens.json assigns stable reference, web and app state IDs. requirements.json maps 22 source criteria to candidate examples. changes.json tracks design and implementation separately. inconsistencies.json tracks open conflicts and owner roles. reference-files.json stores immutable import hashes. project.json records repository setup status.

These JSON files support automation and review; they do not substitute for human approval. GitHub issues are the discussion surface, with durable conclusions reflected back in the registry and change package.
